# 0.2.0 — unpublished release candidate

Add optional, engine-independent change details, portable authored-content anchors, contribution provenance through undo/redo, and host-owned external annotations in editing and read-only rendering. Existing document-only change callbacks remain supported. Canonical Document v2 stays unchanged; no Journal policy, timestamps, storage, or provider credentials enter the package.

Pre-release records are archived under `docs/pre release`. Current consumer API documentation remains in `apps/docs/content/docs`.

## Changes

- Optional typed change details distinguish additions, replacements, deletions, formatting, Reference/Scripture edits, external updates and undo/redo.
- Stable contribution identities survive partial deletion, replacement, splitting, joining, movement and grouped undo/redo. Restored content does not count as a new addition.
- Portable anchors identify authored text by block, optional list item, field and UTF-16 range. Public resolution and explicit identity remapping helpers keep engine positions private.
- Host-owned, non-editable annotations render in editing and read-only views, outside canonical serialization, editor clipboard content and history. The example harness includes an annotation toggle.
- Patched the private documentation app to Next.js 16.3.8 and Sharp 0.35.5 following the dependency audit. Neither is a dependency of the published editor.

## Compatibility and limits

Existing callbacks and Canonical Document v2 remain compatible. Hosts own annotation labels, metadata, persistence and policy, and update annotation anchors from mapped contributions. Annotation placement supports body text, list items, toggle summaries, code, block boundaries, image/video captions and audio transcripts. Active native fields show non-editable labels separately from their values; rendered fields place labels at anchored offsets. Tracking retains 1,000 history-group checkpoints, merging keystrokes within an undo group; unavailable history provenance reports `unresolved` without inventing additions or blocking editing.

## Review corrections

- Fixed whole-document external updates losing surviving contributions. Unchanged text in identified regions retains its provenance; ambiguous recovery is explicitly unresolved, remains unresolved through later edits, and does not assert removals.
- Fixed replacement paste inheriting old contribution identities. Fresh pasted content, including identical-text replacement, receives new identities; typed replacements retain the existing editing policy.
- Added a public version-1 provenance envelope and runtime parser that rejects malformed records, overlapping ownership, duplicate identities and unresolved anchors. Initial tracking metadata is validated rather than silently dropped.

- Completed caption/transcript annotation rendering, contribution restoration and mapping, fresh replacement-paste identities, undo/redo (including shortcuts in active fields), and public field anchor navigation. Native field edits target their owning block even when the engine selection is elsewhere. Standalone image/media components accept annotations and optional field-edit callback details.

Publication remains subject to maintainer approval.

## Verification

On 8 October 2026, after the review corrections and caption/transcript completion, `pnpm check` passed formatting, lint, typechecking, 199 editor tests, 12 docs/example tests, two tooling tests (213 total), production builds, output budgets, package export/type checks, packed-consumer checks on React 18.3.1 and 19.3.0, and dependency-license checks. `pnpm audit --prod` reported no known vulnerabilities. Browser interaction confirmed all three media fields show non-editable annotations in editing and read-only views, active inputs exclude labels from their values, and replacement paste updates authored text. Earlier browser interaction confirmed annotation labels are excluded from read-only text selection. Screenshot capture failed in the collaborative preview, so this change has DOM/interaction verification but no new screenshot-based visual check.

npm publication requires explicit maintainer approval. Phase 5 application integration is separate from this reusable package change.
